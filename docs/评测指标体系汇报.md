# RAGFlow 自动化测试：评测指标体系构建汇报

> 范围：`ragflow_test_automation` 仓库；指标基准为《智能体完整测试指标体系.xlsx》与《企业RAG测试集构建要求》Table5/Table12。

## 摘要

- 43 项指标已全部落到执行层：15 项全自动、16 项半自动复核、12 项人工/演练，自动化抓手占 72%。
- 七个环节端到端可跑：原文解析、召回、重排、回答、引用、拒答、LLM 复核；单题异常不中断整场。
- 最近修复两处 NDCG 口径缺陷，指标从「能算」推进到「算得对」，并补回归测试锁死。
- 尚未出具达标结论：样本量、rerank 连通、自动映射自证三项仍需补齐，已列入下一步。

## 一、项目定位与目标

把 43 项评测指标从「人工填表」变成「可执行、可复现、可追溯」的自动化测试：

- 能全自动计算的指标，一条命令出数；
- 需要人工判断的指标，走规则初筛 + 复核队列；
- 无法量化的指标，输出核查清单与证据要求，**不伪造分数**。

## 三、支撑体系

| 能力 | 实现 | 作用 |
|---|---|---|
| 执行引擎 | `scripts/run_pipeline.py` | 转换→校验→解析→映射→执行→复核→写回，缺条件自动跳过；单题故障隔离，不中断整场 |
| 指标计算 | `src/metrics_retrieval.py`、`src/metrics_generation.py` | 检索侧 8 项 + 生成侧规则分 + 延迟统计 |
| 数据治理 | `validate_dataset.py`、`coverage_check.py`、数据集指纹 | 字段校验、配额缺口检查；sha256+题数+mtime 写入 summary，保证结果可追溯 |
| Chunk 映射 | `export_chunk_candidates_xlsx.py`（人工勾选）、`assist_chunk_mapping.py`（自动映射） | 解决 xlsx 来源拿不到答案 chunk_id 的问题 |
| 复核闭环 | `judge_review.py` | 断点续跑、全量重打、子集限速、先验 prompt |
| 报告 | `report.md` / `summary.json` / `per_question.jsonl` | 阶段门判定、一票否决扫描、场景闭环、RER-Top3、运行异常独立成节 |
| 辅助 | `qa_single.py`、`ragas_like.py`、`parse_benchmark.py` | 单条探针、类 Ragas 四指标下限、解析五项准确率 |

## 四、最近主要功能更新

| 更新项 | 解决的问题 | 价值 |
|---|---|---|
| NDCG 口径修复 | 文档级 gold 下同文档多 chunk 重复计分，NDCG@10 出现 1.32（>1 非法） | 指标合法、可用于验收 |
| NDCG 双重计数修复 | chunk 与文档级 gold 被当两个相关项，完美命中仅 0.61 | 完美命中恢复 1.0，口径自洽 |
| 人工勾选 Chunk 映射 | 此前只有 JSONL 候选，无法人工筛选 | 导出 xlsx 勾选→回收成映射，全流程闭环 |
| 类 Ragas 四指标 | 上下文精确/召回、忠实度、答案相关性缺失 | 提供规则版下限，便于横向对照 |
| 复核体系统一强化 | 量表模糊、思考模型输出非 JSON | 显式 0/1/2 分级 + 拒答铁律 + 三级解析兜底 |
| 单题故障隔离 | 单题异常导致整场中断 | 异常隔离成行，运行异常独立成节 |
| 流水线一键化 | 各步需手工串接 | 自动映射、LLM 复核、写回全部纳入 |
| 8 题冒烟集 | 改配置后全量回归太慢 | 1~2 分钟验证全链路连通 |
| 文档补全 | rerank 引用格式、要点写法无据可依 | vLLM 部署要点、要点原子化、脚本说明齐备 |

## 五、质量保障与可信度治理

- **52 个单元测试全部通过**，纯本地运行、不依赖 RAGFlow 服务，可作为提交前门禁。
- 覆盖：指标边界与回归、xlsx 导入、评判 JSON 解析、勾选回收、报告聚合。
- **指标可信度自查案例（NDCG）**：先发现「>1 的非法值」，再定位到同文档重复计分；修复后进一步发现 chunk/文档双重计数导致「完美命中仅 0.61」。两次修复均补了回归测试，避免口径回退。

| 场景 | 修复前 | 修复后 |
|---|---|---|
| 文档级 gold，5 个同文档 chunk | 1.32 | 1.00 |
| 文档级 gold，首个命中排第 3 | — | 0.6309 |
| chunk 级 gold，完美命中 | 0.6131 | 1.00 |
| 同文档非 gold chunk | 计入命中 | 不计入 |

## 六、当前验证状态

**已跑通**：全链路（检索→回答→引用→拒答）+ LLM 复核端到端；映射→执行→复核→写回闭环可用。

**数据规模**：xlsx 转换问答集 84 题、解析基线 36 题、冒烟集 8 题、手写样例 8 题。

**尚不足以出达标结论**，原因有三，如实说明：

1. LLM 复核仅在 5 题样本上验证（6 个任务各 n=5，RAG-06 仅 1 条有效分），只能证明通道可用、分数有区分度。n=5 时 2/5 的 95% 置信区间约 5%~85%；要支撑「≥95%」需约 60 条零失败样本。
2. 检索侧当前关闭 rerank，重排类指标缺一侧。
3. gold 为自动映射（从同批检索结果中挑选），属自证口径，RAG-01~05 会偏高。

## 七、风险与下一步

| 风险 | 影响 | 措施 |
|---|---|---|
| 自动映射自证 | 检索指标虚高 | 改用 xlsx 人工勾选映射，标注 gold 来源 |
| rerank 未打通 | 重排收益无法度量 | 按文档修正 vLLM 启动参数与全限定引用后重跑 |
| 样本量不足 | 比例类指标无统计意义 | 复核样本扩至 60+，按风险分层抽样 |
| judge 任务重叠 | GEN-01/03、RAG-07/TRACE-02 同分，不独立 | 拆分 rubric，GEN-03 强制逐条核对缺失事实 |
| RAG-06 解析失败 | 有效分仅 1 条 | 修 prompt 与解析，失败项重打 |
