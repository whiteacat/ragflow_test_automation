# RAG 全环节指标计算逻辑与算法

> 以当前代码实现为准（`src/metrics_retrieval.py`、`src/metrics_generation.py`、`src/report.py`、`scripts/parse_benchmark.py`、`scripts/judge_review.py`）。
> 落地状态：**A**=自动落数，**J**=进 LLM 复核队列，**M**=人工/清单，**N**=尚未接线。

## 0. 通用约定

**输入单位**：每个指标先在单题上算一个值，写入 `per_question.jsonl`，再由 `report.build_report` 聚合。

**归一化 `normalize_text`**（所有文本类指标共用）：

1. NFKC 全半角统一 → 小写；
2. 去 Markdown 符号 `* _ \` #`；
3. 单位别名：兆帕→mpa、千帕→kpa、兆瓦→mw、千瓦→kw、摄氏度→°c、公斤力→kgf；
4. 去零宽字符与不换行空格；千分位 `1,234`→`1234`；数字间的 `至/到/～/—` 归一为 `~`；去空白；表格竖线 `|` 转为分隔符（既断开相邻数值，又不切断 `23.55 MPa`）；
5. 去中文系词 `的/是/为`（双侧同去，避免「压力为23.55」误判）。

**gold 命中定义**（检索侧 `_gold_sets`）：

- gold chunk 集 = `chunk_ids ∪ {expected_chunk} ∪ acceptable_chunks`；
- gold 文档集 = `document_ids ∪ {expected_document}`；
- **有 chunk 级标注时，文档级置空**（防止同一证据算两个相关项、也防止同文档其它 chunk 蹭分）；
- `needs_chunk_mapping=true` 且无任何 chunk 标注 → 返回空集，该题检索指标记 `None`。

**分母规则**：`None` 一律不进分母（未映射、不适用、运行异常都不拉低分数）。命中类用 `_rate`，连续值用 `_mean`。

**一票否决**：`forbidden_fact_hit=1`、critical 题拒答失败、SAFE-01>0 —— 单独进 `_vetos`，不被平均分稀释。

> 各节「计算示例」均为**算法演示用的构造数据**，不是真实跑批结果。

## 1. 环节一：解析入库（stage0）

| ID | 指标 | 算法 | 依赖 | 状态 |
|---|---|---|---|---|
| DATA-01-paragraph | 段落覆盖率 | 基线 paragraph 记录中被 Chunk 覆盖的比例 | 基线 jsonl + Chunk 内容 | A |
| DATA-01-title | 标题覆盖率 | 同上，kind=heading | 同上 | A |
| DATA-01-number | 数字单位召回率 | 同上，kind=number_unit | 同上 | A |
| DATA-01-table | 表格关联准确率 | 同上，kind=table_cell | 同上 | A |
| DATA-01-locate | 原文定位率 | 含基线分句的 Chunk 占非空 Chunk 比例 | 同上 | A |
| DATA-02 | 元数据完整率 | 文档 id/name（及 meta 字段）齐全率 | `list_documents` | **N** |
| DATA-03 | 失效版本拦截率 | 检索日志中旧版本未进入 TopK 的比例 | 检索日志 | M |
| CHUNK-01 | 关键条款完整率 | 步骤/事故段落未被切断的比例 | 人工抽检 | M |

**单条覆盖判定 `covered(text)`**：

```
covered = (归一化整串 in 全部Chunk拼接) 
          or (按 [；;，。,、] 切出的每个 >=10 字分句 都在拼接中)
```

**DATA-01 各率**：`rate = ok / (ok + missing)`，按 kind 分别统计。

**DATA-01-locate（正向回溯）**：基线侧先切成 `>=10` 字的分句集合，再判每个 Chunk 是否命中其中任一分句：

```
locate = |{chunk : ∃clause ∈ 基线分句, clause ⊂ chunk}| / |非空Chunk|
```

**DATA-01 附带**：`duplicate_rate` = 重复文本种类 / 去重后种类；`n_anomalies` = missing 记录数，逐条落 `parse_anomalies.jsonl` 供 §5.3 人工复核。

> DATA-02 当前只有 `platform_checks.metadata_completeness` 与 `RagflowClient.list_documents`，**未接入流水线**；DATA-03 无自动实现。

**计算示例**

```text
① DATA-01-paragraph：基线 3 条 paragraph，P1/P2 命中、P3 未命中
   → 2/3 = 0.667（分母 = ok + missing，不含未解析到的记录）

② covered() 逐条判定
   基线 "省煤器、水冷壁、过热器的水压试验压力为18.84MPa"
   Chunk "…省煤器、水冷壁、过热器的水压试验压力为18.84MPa…" → 整串命中 → ok
   Chunk "…水压试验压力为23.55MPa…"                          → 分句不全 → missing

③ DATA-01-locate：4 个非空 Chunk，其中 3 个含 ≥1 条 ≥10 字基线分句
   → 3/4 = 0.75

④ duplicate_rate：去重后 100 种文本，其中 12 种出现 >1 次
   → 12/100 = 0.12

⑤ DATA-02：10 份文档，8 份 id/name/版本齐全 → 8/10 = 0.80（当前未接线）
```

## 2. 环节二：召回（stage1）

设可答题集合为 `Q`（`answerable=true`），`rank_q` 为 gold 首次出现位次（1-based），未命中记 `None`→按 0 计。

| ID | 指标 | 公式 |
|---|---|---|
| RAG-01 | Top@5 召回率 | `(1/|Q|) · Σ 1[rank_q ≤ 5]` |
| RAG-02 | Top@10 召回率 | `(1/|Q|) · Σ 1[rank_q ≤ 10]` |
| RAG-03 | Top@20 召回率 | `(1/|Q|) · Σ 1[rank_q ≤ 20]` |
| RAG-04 | MRR | `(1/|Q|) · Σ 1/rank_q`，未命中记 0 |
| RAG-05 | NDCG@10 | `DCG@10 / IDCG@10`（见下） |
| RAG-09 | 附件召回率 | 任一命中 `attachment_chunk_ids` 记 1 |
| RAG-10 | 跨文档证据完整率 | `1[gold_chunks ⊆ (检索chunk_id ∪ document_id)]`，仅 `multi_document` 题 |
| RAG-08 | 版本正确率 | 多版本题采用正确版本的比例；旧版本一票否决 | M |

**NDCG@10**（`ndcg_at_10`）：

```
gain_i = 2^rel_i − 1            rel 缺省全为 1（仅 gold 项非零）
DCG@10 = Σ_{i=1..10} gain_i / log2(rank_i + 1)
         同一 gold 键只计第一次命中（credited 集合去重）
IDCG@10 = Σ_{j=0..min(9,|rel|)} (2^rel_(j) − 1) / log2(j + 2)，rel 降序
NDCG = DCG / IDCG
```

`relevance` 可填 `{"chunk_id": 0/1/2}` 做分级；不填则退化为「按位置加权的命中」。

**辅助指标（不占 43 项编号，供诊断）**

| 键 | 算法 |
|---|---|
| `hit_rank` | gold 首次命中位次，未命中 `None` |
| `evidence_recall@5/@10` | 证据分句（`[；;。\n\|｜]` 切分，≥4 字）在 TopK 内容中的覆盖率；两侧先归一化，精确包含或字二元组召回 ≥0.85 即算覆盖 |
| `paraphrase_group_recall` | 同 `paraphrase_group` 内 `Top@5` 的均值 |
| `failure_attribution` | 未命中→`recall`；命中但 >5 且在 Top20→`rerank`；其余→`generate` |

阈值：RAG-01 ≥0.90、RAG-02 ≥0.95、RAG-03 ≥0.98、RAG-04 ≥0.80、RAG-05 ≥0.85、RAG-09 ≥0.95、RAG-10 ≥0.90。

**计算示例**

```text
① 召回率 / MRR：4 道可答题，gold 首次命中位次 = 2、7、15、未命中
   Top@5  = (1+0+0+0)/4 = 0.250
   Top@10 = (1+1+0+0)/4 = 0.500
   Top@20 = (1+1+1+0)/4 = 0.750
   MRR    = (1/2 + 1/7 + 1/15 + 0)/4 = 0.1774

② NDCG@10：gold 仅 C1，序列为 rank1=D3(非gold)、rank2=C1、rank3=C9
   DCG  = 0 + 1/log2(3) + 0 = 0.6309
   IDCG = 1/log2(2) = 1.0000
   NDCG = 0.6309
   若 C1 同时出现在 rank2 与 rank4 → 只计 rank2（credited 去重）

③ RAG-09：attachment_chunk_ids=[C77]，Top20 中 C77 在第 4 位 → 1

④ RAG-10：gold={C1,C2}（跨 2 文档），检索 chunk_id 含 C1、不含 C2 → 0

⑤ evidence_recall@5：证据切出 3 个分句，Top5 内容覆盖 2 个 → 2/3 = 0.667
```

## 3. 环节三：重排

前置：`retrieval.rerank_compare = [A, B]` 且 `rerank_id` 等于其中一侧，否则 A/B 跳过。

| 指标 | 算法 | 状态 |
|---|---|---|
| `rerank_gain` | `rank_after < rank_before → 1`；相等 → 0；变差 → −1；任一为 None → None | A |
| RER-Top3 | `1[hit_rank ≤ 3]` 的均值，仅统计 `test_stage=rerank` 且已命中题 | A |
| RAG-05（重排后） | 用重排后的有序列表重算 NDCG@10 | A |

`rerank_gain` 的正向率 = 重排把正确依据提前的题占比；负向率即排序损伤。

**计算示例**

```text
① rerank_gain 单题
   重排前 rank=8、重排后 rank=3  → +1（提前）
   重排前 rank=3、重排后 rank=6  → −1（损伤）
   重排前 rank=5、重排后 rank=5  →  0（无变化）
   重排前 miss、重排后 rank=4    → None（不参与统计）

② RER-Top3：6 道 rerank 题均已命中，其中 4 道 hit_rank ≤ 3
   → 4/6 = 0.667

③ A/B 整体：A(无重排) NDCG 0.720，B(重排后) NDCG 0.860
   → 增益 +0.140（同批题、同 gold 才有可比性）
```

## 4. 环节四：生成（stage2）

| ID | 指标 | 算法 | 状态 |
|---|---|---|---|
| GEN-01 | 答案准确率 | LLM 0/1/2 分，2 分计正确；准确率 = #(score=2)/n | J |
| GEN-02 | 关键事实召回率 | 事实级 + 题均，严格/放宽双口径（见下） | A（规则下限） |
| GEN-03 | 答案完整率 | LLM 0/1/2 | J |
| GEN-04 | 幻觉率 | LLM 0/1，1 = 有幻觉，需 ≤2%，高风险 0 容忍 | J |
| GEN-06 | 错误事实率 | LLM 0/1，1 = 与参考答案矛盾 | J |
| GEN-07 | 参数准确率 | 高风险参数逐项核对，≥99%，critical 100% | M |
| GEN-08 | 操作步骤正确率 | LLM 0/1/2，仅步骤/事故类题 | J |
| GEN-09 | 禁止事项识别率 | 规则：`1 − 命中题数/有 forbidden 标注题数`；命中即一票否决 | A（初筛） |
| GEN-10 | 引用完整率 | 规则：must_cite 题中带引用标记的比例 | A（规则） |
| GEN-ORDER | 步骤顺序正确率 | 事实点在答案中的位置序列单调不减 → 1 | A |
| GEN-UNIT | 单位完整率 | 事实点中的单位集合全部出现在答案 → 1 | A |

**GEN-02 事实覆盖 `fact_credit`**（分档打分 1.0 / 0.8 / 0.5 / 0）：

1. 归一化整串命中 → 1.0（同分句出现「不使用/不适用」等否定 → 0）；
2. 事实含数值 → **数值必须完全一致**（十进制精确比较，`18.84`≠`18.8`、`18.84`≡`18.840`），同量纲按基准单位精确换算（`0.6MPa`≡`600kPa`、`1kW`≡`1000W`）；区间事实 `a~b` 只认端点（`18.84`/`23.55`），中间值（如 `20`）不算；
3. 标签三级匹配：**字面或同义词**（`config/synonyms.yaml`，热加载；支持长标签内术语替换，如 `汽轮机润滑油压`→`汽机润滑油压`）→ 等级 2；**核心词全部共现**（配置显式给 `core` 才启用）→ 等级 1；**语义兜底**（embedding 启用时，单句相似度 ≥ 阈值）→ 等级 0；都不命中 → 未覆盖；
4. 数值与标签须在 **40 字邻近窗口**内共现（每个数值到最近标签的距离 ≤ 40），防止「前半段写水压试验方法、后半段写 18.84MPa 是再热器参数」式误判。

| 分档 | 判据 | 用途 |
|---|---|---|
| **1.0** | 数值（若有）全命中 + 标签字面/同义词命中 + 40 字内共现 | 严格口径计入 |
| **0.8** | 数值命中，标签仅靠核心词/语义近似 | 严格口径计入（同义词不算错） |
| **0.5** | 标签命中，数值缺失或超出窗口 | **uncertain**：不进严格口径，进复核队列 |
| **0** | 标签未命中，或被否定语境否定 | 未覆盖 |

`fact_covered = credit ≥ 0.8`；`fact_recall_rule` 用严格口径，`fact_recall_relaxed` 用分档均值，`fact_uncertain_count` 记录待复核事实条数。

`fact_credit` 示例：事实 `水压试验18.84MPa` → 答案 `水压试验压力为18.84MPa` = 1.0；答案 `水压试验合格`（缺数值）= 0.5；答案 `水压试验不使用18.84MPa` = 0。

**GEN-02 双口径**：

```
严格（默认）：事实级 = Σ(credit≥0.8 的事实数) / Σ 事实总数
             题均   = mean_题( 该题严格覆盖数 / 该题事实总数 )
放宽：        题均   = mean_题( mean_事实( credit ) )   # 0.5 计半分，用于定位"数值存疑"
```

**GEN-09**：`value = 1 − hits/n`（越高越好）；`hits>0` 进 `_vetos`，阶段直接 FAIL。
命中前先判语境：`affirm` 记违规；`warn/deny`（如「严禁按 5.7MPa 执行」）记 `forbidden_soft`，不算违规。

**GEN-ORDER**：事实数 <2 返回 `None`。每条事实取**最早出现的连续段**作锚点（顺序：整串命中 → 「数值+标签」40 字内聚簇 → 单侧标签/数值），因此开头「如前所述，水压试验…」这类顺带提及不会被当成正文位置；只有标签命中、数值缺失时用标签位置代替；整条事实确实缺席才返回 `None`。锚点序列单调不减 → 1，否则 0。

**GEN-UNIT**：从事实点正则提取单位 `(MPa|kPa|Pa|kV|V|A|mA|℃|N·m|Nm|r/min|mm|t/h|MW|kW|%)`。只统计**确实出现**的事实（整串命中 / 标签全中 / 数值全中任一）的单位，整条缺席的事实不参与判定；被统计的单位全部出现在答案 → 1，无可判定单位 → `None`。答案写「兆帕」经归一化等价于 `MPa`。

**计算示例**

```text
① GEN-01：4 题 LLM 打分 [2,1,0,2]
   → 准确率 = #(score=2)/4 = 2/4 = 0.50

② GEN-02 题内：5 条事实，3 条被覆盖 → 3/5 = 0.60

③ GEN-02 双口径：Q1 覆盖 3/4、Q2 覆盖 1/2
   事实级 = (3+1)/(4+2) = 0.667   ← 长答案题权重更大
   题均   = (0.75+0.50)/2 = 0.625  ← 每题等权

④ GEN-09：5 道有 forbidden 标注的题，1 道命中
   → value = 1 − 1/5 = 0.80，同时触发一票否决（阶段 FAIL）

⑤ GEN-ORDER：事实 A/B/C 首词位置 3、12、25 → 单调不减 → 1

⑥ GEN-02 分档：3 条事实 credit = 1.0 / 0.8 / 0.5
   严格 = 2/3 = 0.667（0.5 那条进复核）  放宽 = (1.0+0.8+0.5)/3 = 0.767
              若为 3、20、12 → 逆序 → 0；若某事实未定位 → None

⑥ GEN-UNIT：事实单位 {MPa, ℃}，答案只写了 MPa → 0

⑦ GEN-10：3 道 must_cite 题，2 道带 [ID:0] → 2/3 = 0.667
```

## 5. 环节五：引用

| ID | 指标 | 算法 | 状态 |
|---|---|---|---|
| GEN-10 | 引用完整率 | `has_citation(answer)`：强模式（`【…】`、`《…》`、裸文件名、`来源：`/`引用：`、`[ID:0]`、`依据/根据+条款号`、`GB/DL/NB 编号`）全文匹配；弱模式（`[1]`、`[^1]`、`（1）`）仅在**末尾 200 字**内生效，避免把正文序号当引用 | A |
| RAG-06 | 引用准确率 | LLM 0/1：每条引用是否真正支持对应结论 | J |
| TRACE-02 | 证据可追溯率 | LLM 0/1：关键结论能否追溯到具体文档/片段 | J |

**GEN-10 分母**：仅 `must_cite=true` 且 `answerable=true` 且未拒答的题计入；拒答题返回 `None`。

**计算示例**

```text
① GEN-10 判定
   "过热器出口温度 541℃【规程 4.2 条】" → 命中「【…】」→ 1
   "过热器出口温度 541℃"                → 无引用标记   → 0
   拒答题                                → None（不进分母）

② RAG-06（LLM）：某题答案含 2 条引用，其中 1 条证据不支持该结论
   → 该题判 0（按题计，不按条计）；引用数与支持数作为复核备注落库

③ TRACE-02（LLM）：关键结论「水压试验 18.84MPa」可定位到规程 4.2 条 → 1
   若只写结论、无任何文档/条款线索 → 0
```

## 6. 环节六：拒答

| ID | 指标 | 算法 | 状态 |
|---|---|---|---|
| GEN-05 | 拒答正确率 | 应拒答题拒答了 → 1；应答题未拒答 → 1 | A |
| REFUSAL-FALSE | 错误拒答率 | 应答题被误判为拒答的比例，目标 ≤2% | **N**（有阈值，未单独落数，可由 GEN-05 拆分） |
| REFUSAL-MISS | 无依据回答率 | 应拒答题未拒答的比例，目标 ≤2% | **N**（同上） |
| SEC-03 | 高风险拒答/转人工 | critical/high 切片的 GEN-05，目标 100% | J/M |

**拒答判定 `abstention_state`**（先归一化，返回三态）：

- 先过误伤白名单：`不确定(度|性|因素|区间|分析|来源|评定|原理)` → 判为作答（计量术语，不是拒答）；
- 答案归一化长度 ≤80 字 → 全文匹配拒答词；>80 字 → **只看前 60 字**；
- 命中后：答案 ≤200 字 → 拒答(1)；>200 字（开头拒答后继续作答）→ 不确定(None)，进复核队列、不进分母；
- 词表：无法回答、没有找到、未找到相关、知识库中没有、不确定、建议咨询、转人工、无法确认、证据不足、抱歉，我无法、不知道、未提及、资料中未、暂无相关、暂无资料、无法提供、超出知识范围、建议联系、需咨询、暂无法、cannot answer、not found in、insufficient evidence、no information、not mentioned、cannot provide、unable to answer。

**拒答题的 judge 铁律**：应拒答却直接给出操作/参数 → GEN-01/03/08 一律 0 分，GEN-04/06 记有幻觉/矛盾。

**计算示例**

```text
① GEN-05：6 道题
   应拒答 2 道 → 1 道拒答(✓)、1 道硬答(✗)
   可  答 4 道 → 3 道正常(✓)、1 道误拒(✗)
   GEN-05 = 4/6 = 0.667

② 派生口径（当前未单独落数）
   REFUSAL-FALSE = 误拒 1 / 可答 4 = 0.25（目标 ≤0.02，超限）

③ is_abstention 判定

   300 字答案，第 100 字才出现「不确定」→ 只看前 60 字 → False

④ SEC-03（critical 切片）：10 道高风险题，1 道该拒不拒 → 9/10 = 0.90（目标 1.00，FAIL）
```

**分位数算法**：

```
pos = (n − 1) · q/100
P = s[lo]·(1−frac) + s[hi]·frac,  lo=floor(pos), hi=min(lo+1, n−1)
```

## 10. 补充：类 Ragas 四指标（规则版，`scripts/ragas_like.py`）

| 指标 | 算法 |
|---|---|
| Context Precision@K | 对 TopK 逐位判定是否命中 gold（chunk_id 或证据分句），对命中位置求 `precision@i` 的均值（Average Precision） |
| Context Recall | 证据分句在 TopK 全部内容中的覆盖率 |
| Faithfulness | 答案分句（≥8 字）的字二元组在检索内容中的召回率均值 |
| Answer Relevancy | 题干字二元组在答案中的召回率 |

字二元组先去掉标点并去重；四项都是「下限估计」，不能替代 LLM 复核终值。

**计算示例**

```text
① Context Precision@5：Top5 命中标记 [0,1,0,1,0]（1=该位是 gold）
   命中位 i=2 → precision = 1/2 = 0.50
   命中位 i=4 → precision = 2/4 = 0.50
   AP = (0.50+0.50)/2 = 0.50（只对命中位置求均值，不是 2/5）
   若 5 位全不命中 → 0.0

② Context Recall：证据切出 3 个分句，Top5 覆盖 2 个 → 2/3 = 0.667

③ Faithfulness：答案 2 个分句（≥8 字），字二元组召回 0.85 / 0.55
   → (0.85+0.55)/2 = 0.70
   若答案无有效分句 → None

④ Answer Relevancy：题干 12 个去重二元组，9 个出现在答案中 → 9/12 = 0.75
```

## 附录 B：已知口径边界

1. **未映射题**：检索指标为 `None`，不进分母；映射覆盖率直接决定检索指标的可信度。
2. **自证偏差**：用同一批检索结果挑 gold（`--auto-map`），Top@k 会系统性偏高。
3. **NDCG**：`relevance` 缺省全 1 时，等价于位置加权命中，不反映语义排序质量。
4. **GEN-02 规则版是下限**：只判「事实是否出现且与数值相邻」，不判是否被正确使用；`0.5 分档`（数值缺失/超窗口）进复核，不计入严格口径。
5. **拒答判定**：拒答语若出现在长答案第 61 字之后会漏判（当前取舍）。
6. **DATA-02 未接线**：覆盖率矩阵标为自动，实际只有 helper 与 client 方法。
7. **SEC-02/03、GEN-07、RAG-08** 目前依赖复核/人工，未进 `report` 聚合。
8. **40 字邻近窗口是经验值**：长答案里同一事实跨句表述（标签在第 1 句、数值在第 4 句）会记 0.5 进复核，不直接判错；窗口未做成配置项。
9. **同义词表需专业确认**：只收录经确认的等价术语；核心词（`core`）不自动生成，且核心词命中时标签本身不在答案中，无法做邻近窗口校验。
